### 审查发现的问题

#### 问题1: MoeyuAPIClient.loadUserData() 迁移逻辑中 FileInputStream 未关闭
- **文件**: `MoeyuAPIClient.java:97`
- **严重程度**: 中
- **描述**: 迁移旧版数据时 `new FileInputStream(legacyFile)` 后未在 finally 块中关闭流。虽然 `UserData.restore()` 内部会调用 `ois.close()`，但如果反序列化抛出异常，FileInputStream 可能不会被关闭。
- **建议修改**: 使用 try-with-resources 或在 catch/finally 中显式关闭流。
- **实际风险**: 低。`UserData.restore()` 内部 catch 了所有 Exception 并调用了 `ois.close()`，且Android在GC时会回收文件描述符。但作为代码规范应修正。

```java
// 建议改为:
try (FileInputStream in = new FileInputStream(legacyFile)) {
    sUserData = UserData.restore(in);
    Logger.d("UserData", "已从旧版数据文件迁移用户数据");
} catch (FileNotFoundException e) {
    Logger.e("UserData", "迁移失败：旧版文件未找到");
}
```

#### 问题2: BaseTask每次创建新MoeyuAPIClient实例可能触发重复数据加载
- **文件**: `BaseTask.java:24`
- **严重程度**: 中
- **描述**: `BaseTask` 构造函数中 `new MoeyuAPIClient(context)` 每次都会调用 `loadUserData()`。在快速连续操作（如连续抽卡）时，多个 AsyncTask 可能各自创建 MoeyuAPIClient 实例并重复加载数据。由于 `sUserData` 是静态变量，后创建的实例会覆盖先创建的数据。不过由于 `sUserData` 是引用赋值且最终都会从文件读取最新数据，实际数据丢失风险较低。
- **建议修改**: 可考虑在 `MoeyuAPIClient` 中判断 `sUserData != null` 时跳过 `loadUserData()`，或引入单例模式。
- **实际风险**: 低。当前使用场景下，AsyncTask是串行执行的，且静态变量确保了数据引用一致性。

#### 问题3: getGachaResult() 是静态方法但操作静态变量 sUserData
- **文件**: `MoeyuAPIClient.java:219-235`
- **严重程度**: 低
- **描述**: `getGachaResult()` 被声明为 `private static`，但内部直接访问和修改静态变量 `sUserData`（通过 `sUserData.getItems()`、`sUserData.addItem()` 等）。这在设计上不一致——静态方法不应该依赖静态可变状态。虽然功能正确，但增加了代码理解的复杂度。
- **建议修改**: 将方法改为实例方法，或在方法签名中显式传入 UserData 参数。

#### 问题4: GatyaActivity.executeBilling() 中白金币购买缺少上限校验完整性
- **文件**: `GatyaActivity.java:446`
- **严重程度**: 低
- **描述**: `buyPlatinumButtonClick()` 中使用 `>= MAX_COIN` 判断（即 `>= 99`），但 `buyGoldButtonClick()` 中使用 `+ c > MAX_COIN` 判断（即 `+数量 > 99`）。白金币按钮逻辑是"已满时不能买"，而不是"买了之后超过上限不能买"。如果白金币为98枚，购买1枚后变成99枚，逻辑仍然正确。但如果未来产品ID对应的数量发生变化，此处校验需要同步更新。当前逻辑与实际行为一致，仅提示注意一致性。
- **实际风险**: 无。当前 `platinum_coin_1` 固定赠送1枚，与 `>= 99` 逻辑兼容。

### 改进建议

1. **遗留URL**: `TitleActivity.showTerms()` 中仍有一个 `http://www.moe-yu.com/kiyaku.html` 的外部URL跳转（第192行）。这属于服务条款链接，非API调用，保留是合理的，但建议在文档中标记为已知的外部URL。

2. **INTERNET权限**: `AndroidManifest.xml` 保留了 `INTERNET` 和 `ACCESS_NETWORK_STATE` 权限。当前仅用于服务条款URL跳转（隐式Intent打开浏览器），应用本身不发起网络请求。如果希望彻底离线化，可考虑移除并在应用内内置服务条款文本。但保留也不会造成功能问题，仅作为建议。

3. **数据迁移完成后清理**: 建议在成功从 `localUserData.dat` 迁移数据后，删除旧文件以避免后续重复迁移判断。当前迁移成功后旧文件仍然保留在 cacheDir 中。
