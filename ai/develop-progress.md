## 五、进度跟踪机制

### 5.1 进度汇报频率

| 汇报类型 | 频率 | 参与方 | 内容重点 |
|---------|------|--------|---------|
| 每日站会 | 每日 15 分钟 | 全体开发 AGENT | 昨日完成、今日计划、阻塞问题 |
| 周进度报告 | 每周一次 | @product-manager + 各 AGENT | 本周完成情况、下周计划、风险更新 |
| 里程碑评审 | 每个阶段结束 | 全体 AGENT + 利益相关者 | 阶段成果评估、质量门禁检查、下一步规划 |

### 5.2 进度可视化

**看板列设置**:
- TODO（待处理）
- IN_PROGRESS（进行中）
- IN_REVIEW（审查中）
- BLOCKED（阻塞）
- DONE（已完成）

**度量指标**:
- 任务完成率 = 已完成任务数 / 总任务数 × 100%
- 测试覆盖率 = 已覆盖代码行数 / 总代码行数 × 100%
- 构建成功率 = 成功构建次数 / 总构建次数 × 100%
- 缺陷密度 = 发现缺陷数 / 千行代码

### 5.3 质量门禁

| 门禁阶段 | 检查项 | 通过标准 |
|---------|--------|---------|
| 代码提交 | 静态代码分析 | 无 Critical 级别问题，Warning ≤ 10 |
| 构建验证 | 自动化测试 | 单元测试通过率 ≥ 95% |
| 集成审查 | 代码审查 | Code Review 批准，技术债务不新增 |
| 发布验收 | 端到端测试 | 功能测试通过，性能指标达标 |
